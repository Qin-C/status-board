# 方案板草稿格式速查

你只写一份短 Markdown 草稿,`plan.py` 把它拼成网页,并在生成时检查;不合格不出页面。
完整例子:`examples/board-proposal-redesign.md`(合格)· `examples/bad-wall-of-text.md`(被拦下)·
`examples/good-numbers-as-bars.md`(额度页:先给框、附通过的冷读记录)· `examples/bad-numbers-only-table.md`(只有表格)·
`examples/bad-jargon-no-frame.md`(有图,但词没解释、没说是哪种额度)。

```bash
python3 ~/.claude/scripts/plan.py lint   草稿.md [--strict]      # 只检查
python3 ~/.claude/scripts/plan.py render 草稿.md -o 输出.html     # 先检查,有 error 不出页面(退出码 1)
python3 ~/.claude/scripts/plan.py patch  输出.html --section "节标题或序号" < 新的一节.md
python3 ~/.claude/scripts/plan.py coldread 草稿.md [--save 回答.json | --check]   # 发之前冷读,见「发之前:冷读」
python3 ~/.claude/scripts/plan.py selftest
```

- `render` 的草稿写 `-` 表示从标准输入读(此时必须给 `-o`)。
- `patch` 只换那一节(连同目录、顶部「有几件要你定」、内嵌的草稿原文),其余字节不动,原地写。
  新的一节必须以 `## 标题` 开头且只有这一个 `##`;换完整页检查不过 ⇒ 报错、文件不动。

## 骨架

```markdown
---
title: 状态板与方案板 · 优化方案
line: 状态板线
date: 2026-10-06
status: 提议中
---

**结论:两处要动。** ① 状态板改成直接点选。② 方案板由工具生成。

## 方案板改成由工具生成页面

正文、图、要他定的题……

## 不改什么

配色和三块结构都不动。
```

- frontmatter 四项必填;`date` 写 `YYYY-MM-DD`;`status` 只能是 `提议中` 或 `已定`。
- frontmatter 后**第一段 = 结论**(必填,≤120 字)。
- `## 标题` = 一节,自动编号。标题是一句完整的结论(≥6 个字,不以冒号结尾)。`## 不改什么` 例外放行,鼓励写。
- 节内可用 `###` 小标题。草稿里的原始 HTML 一律被转义,不会生效。

## 零件(围栏块)

### decision — 要他定的题

````markdown
```decision
方案板归谁管？
cost: 现在没人管。不定的话这套工具没人能动。
- *状态板线接管 | 结构、工具、检查归我。
- 仍归设计系统线 | 我把这份方案交给它做。
```
````

- 第一行是问题;`cost:` 写不定会卡住什么;选项 `- 标题 | 说明`,至少 2 个。
- 恰好一个选项以 `*` 开头(`- *标题 | 说明`)= 建议,页面上默认选中。
- 「其他(我自己写)」选项和多行补充框由工具自动加,**不要自己写**。
- 题的 id 默认由问题文字算出(问题一改,旧答案就不再对上)。两道题问法相同、或想让 id 稳定,加一行 `id: owner-plan`。
- 题不能放进 fold。

### batch — 按组批量定(一题定一组条目)

负责人 11-13 在 105 道题的页上:「我不可能点105次」。同类的条目(都下架 / 都上架 / 都按建议改价)合成一道:

````markdown
```batch
这 87 条都下架？
cost: 不定的话这批链接继续占着广告预算。
id: delist-87
- *都下架 | 30 天 0 单,留着只花钱。
- 都先留着 | 等大促后再看。
items:
- 链接 A-001 | 30 天 0 单
- 链接 A-002 | 退货率 40%
- 链接 A-003
```
````

- 问题 / `cost:` / `id:` / 选项写法同 decision;问题写这组的共同结论。
- `items:`(或 `清单:`)之后每行一条 `- 条目名 | 一句理由`(理由可不写),至少 2 条,条目名不重复、不超过 60 字。
- 页面上:点一个选项 = 定了整组;清单默认收起,展开后个别条目勾「例外」。
- 例外按**条目名**记进回答;AI 侧 `board.py answers` / 叫醒文本里印「整组选了「都下架」,例外:条目 链接 A-002」。
- 一页超过 10 道题会提醒(`dec-many`,只提醒,`--strict` 也不拦):把同类的合成一道 batch。

### batch — 每一行各自选

条目少、看一份清单就能决定时，用「每行选」。每个选项要先看一段介绍时，用下面的「节内选」。

在 `items:` 之前用一行 `每行选: 涨 | 不涨` 替换整组选项。保留题面、`cost:`、可选的 `id:` 和原来的条目清单。选项用 `|` 分开，最多 5 个，每项都有文字且不重名。「没选」是空行的回答。

每行单选，默认留空，可以取消已选项或写一句补充。在服务上点一次「全部发给 AI」，`board.py answers` 按条目逐行列出所选及补充，空行显示「没选」。「生成回复」也会逐行列出。

完整草稿见 [逐行选择样例](examples/good-batch-rows.md)。第一次给旧页面加逐行题时用新版 `render`，之后可用 `patch` 换节。

### 节内选 — 每节看完当场选

在需要决定的 `##` 节里独立写一行 `选: 涨 | 不涨`。可紧接一行 `建议: 涨`，给本节已有的一个选项加「建议」标记。选项放在该节正文末尾，默认留空，可取消或补充。每节最多 5 个非空且不重名的选项，「没选」保留给空行。节名须唯一，同页只能选用节内选和 batch「每行选」中的一种。

所有节内选合为一道题，页末「已选汇总」按节顺序显示当前选择，点一行回到该节。点一次「全部发给 AI」，`board.py answers` 会按节名列出选项和补充。未选的节显示「没选」。

可在页首 frontmatter 写 `pick_question:`（题面，默认「请逐节选择」）、`pick_id:`（题 ID，默认 `pick.per-section`）和 `pick_cost:`（不定会卡住什么，可省略）。自定义 ID 以字母开头，只用字母、数字、横线和下划线。行 ID 由题 ID 和节名生成，题 ID 或节名变动会生成新行 ID。

完整草稿见 [节内选择样例](examples/good-pick-per-section.md)。第一次给旧页面加节内选时用新版 `render`，之后可用 `patch` 换节。

### flow — 流程图

````markdown
```flow
✕ 现在
AI 手写整页网页 -> 没人查 -> 你在聊天里打字回答
✓ 改成
AI 只写草稿 -> !工具拼页面 | 图和选项是零件: 当场检查
工具拼页面 -> 你点选项
cap: 图下面的一句说明(可不写)
```
````

- 一行一条 `A -> B: 标注`;也可以连写 `A -> B -> C`(标注只落在最后一段)。标注用**英文冒号**,尽量 ≤8 个字。
- `!A` = 强调这个节点;`A | 小字` = 节点第二行小字。同名节点是同一个方框。
- `✕ 标题` / `✓ 标题` / `@ 标题` 另起一条泳道(红 / 绿 / 中性),不写就是一条中性的。
- 方框按出现顺序从左到右排,一行放不下自动折到下一行。

### compare — 前后对比

````markdown
```compare
✕ 现在的一页
> 一大段原样的长文字(以 > 开头:渲染成淡色、截断的「文字墙」)
cap: 32 步纯文字,没有图。
✓ 改后的一页
**1 上新分四段,只有第三段要人看。**
`登记` → `写文案` → `出图` → `上架`
cap: 标题是结论,图在前。
```
````

两栏都要有;每行一条短文字(可用行内 Markdown);`cap:` 是这一栏的图注。

### bars — 条形图

````markdown
```bars
你答了,板还挂着 | 13 | 13 | 13　上周 8
在做的活看不出到哪了 | 4 | 13 | 4　上周 8 | ok
cap: 图下面的一句说明(可不写)
```
````

`标签 | 数值 | 满格值 | 右侧文字 | ok`。数值、满格值必须是数字;满格值不写 = 取本图最大值;
右侧文字不写 = 显示数值;第 5 格写 `ok` = 绿色条(默认红色)。中间格不写可以空着:`甲 | 270 | | 约 270 | ok`。

**分组**(几种方案比几项用量):`@ 组名` 单独一行起一组,下面照常写条;整张图共用一把尺子,组和组之间也能直接比。

````markdown
```bars
@ 3C 24 家 · 每周次数
每天全扫 | 950
按店名筛导出 | 150 | | 150 | ok
@ 女装 10 家 · 每周次数
每天全扫 | 400
按店名筛导出 | 60 | | 60 | ok
```
````

组名不能空,一组下面至少一条。

### steps — 分步卡片

````markdown
```steps
第 1 步 · 2 天 | 方案板工具第一版 | 拿一页真方案重做给你看。
第 2 步 · 3 天 | 在板上直接答 | 点完当场记下。
```
````

### fold — 收起的细节

`````markdown
````fold 细节:五类检查各查什么
这里是普通 Markdown,默认收起。里面还要放别的围栏块时,外层用 4 个反引号。
```bars
甲 | 1 | 2
```
````
`````

标题写在围栏同一行。fold 里的字和图不算「露在外面」。

### draft — 要他审的原稿(图文审稿用)

`````markdown
````draft 小红书正文
第一段正文……(原样贴,不用压字数)

![封面](img/01.png)
![第二张](img/02.png)
````
`````

- 要他审的稿本身(社媒正文、串推、配图、长文)放这里:单列排、字号大一点;**同一段里的几张图排成网格**,在 8777 上**点任一张图全屏看**(←/→ 翻页)。
- 稿里的字**不算**页面字数上限(稿多长是稿的事);标题算。稿里有图 = 这一节有图。
- 题(decision)不能放进 draft。几份稿就写几个 draft 块,⛔ 别手写左右两栏把两段长文并排。
- ⚠ 选品的 `review.py` 只给**上架对标**(对标主图左、我们右逐张并排)用;别的线审图文一律 plan.py + draft,⛔ 别套选品模板(负责人 10-28)。

### 盘点 / 对比 / 用量:先图后表

11-17 一页全是表格的额度盘点被评「可视性可读性几乎为零」。凡是**比数字**的(各用途每天几次、
几种方案各花多少、前后差多少),先放一张 ```bars 把差距画出来,表格只当明细,收进 ```fold。

````markdown
```bars
现查销量走势 | 50 | | 50 次/天
补商品资料 | 30 | | 30 次/天
换图兜底 | 8 | | 8 次/天 | ok
cap: 合计约 105 次/天。
```
```fold 明细表:每个用途现在怎么拿、能换成什么
| 用途 | 现在怎么拿 | 每天次数 | 能换成 |
|---|---|---|---|
| 现查销量走势 | 逐个现查 | 50 | 导出里没有就判不达标 |
```
````

几种方案比几项用量 ⇒ 用上面 bars 的 `@ 组名` 分组。
一节里露着一张比数字的表(≥3 行数据,某一列六成以上是数)而没有图 ⇒ 报 `nums-nofig`,
报错下面直接给一段拿这张表前三行拼好的 ```bars,核一下数就能贴。不算数字列的:纯文字说明、序号 1/2/3、日期 / 时刻、
10 位以上的编号(商品号)、一列数全一样(全是 0)、一列单位不一(42 次 / 25 行:每行是不同指标);超过 30 行的表当清单不查。

### 讲数量:先给框

讲额度 / 配额 / 上限,先让读者知道**是哪一种、多大、按什么周期、够不够**,再讲细节。光有图不够:
图画得再清楚,读者不知道「这是哪种额度」照样看不懂。写 ```quota,一行一种额度,五栏都必填:

````markdown
```quota
导出额度 | 200 次 / 周 | 120–140 | 7 | 下载销量榜、每天导出同类店清单
查询额度 | 每月最多 3,000 次 | 2,400–2,600 | 0 | 补商品详情
cap: 「已用」是最近 4 周里最少到最多的那一周。
```
````

五栏 = 名称 | 上限与周期(周期:天 / 周 / 月,月按 30 天折算)| 已用(可写区间、约)| 接下来要用 | 用在哪。
机器算:大字上限 + 折成每天、刻度条、一句「够 / 不够 / 可能不够,还剩或超出多少」(正好用满算够)。缺一栏 ⇒ `quota` 报错并点名缺哪栏。
露在外面的字提到额度 ≥2 次却没有 quota 块 ⇒ `quota-missing`(warn,`--strict` 拦)。

### 普通 Markdown

段落、`-` / `1.` 列表(可缩进嵌套)、表格、`>` 引用、`**粗**`、`*斜*`、`` `代码` ``、
`[链接](地址)`(新标签页打开)、`![说明](相对路径或 http 地址)`、其他语言的代码块。
图片的相对路径是相对**输出的 html** 算的。

## 检查规则

每条报错都带草稿行号、哪里不对、一个写对的例子。

| 级别 | 代码 | 规则 |
|---|---|---|
| error | `meta` | frontmatter 缺项、date 格式不对、status 不是两个值之一 |
| error | `lead-missing` / `lead-long` | 没有结论段 / 结论超过 120 字 |
| error | `head-short` / `head-colon` | 节标题不足 6 个字 / 以冒号结尾 |
| error | `sec-wall` | 一节露在外面的文字超过 300 字,而这一节没有任何图 |
| error | `page-long` | 全页露在外面的文字超过 2500 字 |
| error | `page-nofig` | 超过 800 字的页面一张图都没有(表格不算图) |
| error | `dec-opts` / `dec-sug` / `dec-cost` | 题少于 2 个选项 / 没有或有多个建议 / 没写 `cost:` |
| error | `dec-dup` / `dec-fold` | 两道题 id 相同 / 题写在 fold 里 |
| error | `rel-date` | 出现 今天 / 今晚 / 明天 / 昨天 / 明早 / 今早 |
| error | `syntax` | 围栏没关、零件里的行写得不对 |
| error | `cell-long` | 表格一格超过 60 个字(fold 里的表格不查) |
| error | `batch-items` | 按组题清单少于 2 条 / 条目名重复 / 条目名超过 60 字 / 清单行写不对 |
| error | `batch-row-options` | 每行选项为空 / 超过 5 个 / 重名 / 占用「没选」/ 与整组选项混用 |
| error | `section-pick` | 节内选项为空 / 超过 5 个 / 重名 / 占用「没选」/ 节名重名 / 建议不在选项中 / 与每行选混用 |
| warn | `nums-nofig` | 一节露着一张比数字的表(≥3 行数据,某一列六成以上是数),这一节却没有图:先放 bars,表收进 fold |
| warn | `dec-many` | 一页超过 10 道题(只提醒,`--strict` 也不拦):合成按组批量定 |
| warn | `sent-long` | 一句话超过 45 个字 |
| warn | `para-long` | 一段超过 6 句 |
| error | `quota` | quota 块缺栏 / 多栏 / 上限、已用、接下来要用写不成数 |
| warn | `quota-missing` | 露在外面的字提到额度 ≥2 次,却没有 quota 块 |
| error / warn | `coldread` | render / patch 时没有冷读记录、指纹对不上、还有标 `blocks:true` 且没豁免的条目:有题的页 error,只展示的页 warn |

warn 不拦;`--strict` 时当 error。口径:

- **字数** = 去掉空白后的字符数(汉字、标点、字母、数字各算 1)。
- **露在外面的文字** = 结论、节标题、段落、列表、引用、小标题、fold 的标题、图注。
  fold 里面的、表格格子、题、图里的字**不算**进 300 / 800 / 2500。
- **图** = flow / compare / bars / steps / quota / 图片,而且要露在外面(fold 里的不算)。表格**不算图**(`page-nofig`、`nums-nofig`);
  只有 `sec-wall` 把表格当图(表格里的字本来就不算正文字数)。
- `rel-date` 查所有露在外面的字,**包括**表格、题、图里的字;只有 fold 里和反引号里的不查。
  要引用界面上的字就写成 `` `今天新增` ``。
- `sent-long` 按 。！？；和换行断句;查结论、正文、图注、题;代码和链接地址不算。

## 发之前:冷读

作者有上下文,自己读不出哪里看不懂。所以生成前,让一个**不带任何上下文**的便宜子代理读一遍他会看到的全部文字:

1. `plan.py coldread 草稿.md` ⇒ 导出 `草稿.coldread.txt`(首行带指纹),并打印任务书。patch 前用 `coldread 输出.html --section 节 < 新的一节.md`。
2. 派冷读者:精简子代理(`lean-worker`,没有就 `worker`)+ 便宜模型,prompt 开头写 `[no-worktree]`,其余只给任务书。精简子代理开局固定开销小一半。
3. `coldread 草稿.md --save 回答.json` 存成 `草稿.coldread.json` 并核对;`--check` 只核不存。

- 冷读者给每个读不懂的词、答不上的问题标 `blocks`:只有「不懂它就看不懂这页 / 答不了要定的题」和「做决定必需却没给的信息」标 true。
  只有 true 的拦(改正文);false 的只印出来参考,不拦、不用豁免。没写 `blocks` 的旧记录按 true。
- 改了正文指纹就变,要重读。挡路的条目确实不该改时写 `"waived": "≥8 个字的理由"`,render 时记入提醒日志。
- render / patch 会查这份记录:有题(decision / batch)的页没过 ⇒ error,不出页面;只展示的页 ⇒ warn(`--strict` 拦)。来不及:`--no-coldread "≥8 个字的原因"`,照出页面但记日志。
- 否掉的做法:内部词表(追不上新叫法,查到有定义也不等于读者懂);作者自己答(有上下文等于没查);
  让冷读者把想到的都列上(实测一页改 8 轮也读不到全空,最后只能满页写豁免)。

## 页面自带的东西(不用写)

- 单栏,最大宽 820px,浅色;目录是顶部一条默认收起的条,列各节和每道题(没答红、答了绿)。
- 右下角「还有 N 个要定 ↓」和「生成回复」。回复只复制到剪贴板,不自动发送。
- 他一点选项或写补充,页面 `POST /_answer` 记到本机服务;打开时 `GET /_answers?page=<文件名>` 读回,
  题头显示「你 MM-DD 答了:…」。接口不存在时页面照常工作(此时只在浏览器本地留一份)。
- 页面里内嵌了草稿原文(`<script type="text/plain" id="plan-source">`),`patch` 靠它。

## 改样式

`plan.css` 和 `plan.js` 由 `plan.py` 读进来内联进每一页;不要引任何外部网址。
改了它们之后,旧页面要重新 `render` 才会换上新样式(`patch` 不动样式)。
