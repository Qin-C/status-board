状态板可视化原语速查

左边是渲染效果，右边是逐字可抄的写法。lint 查不出「标记写错」——孤儿类为零也可能整块塌掉，只有渲图看得见。照这里抄能省掉那一轮。

先记一条通则 + 三条最容易踩的

⭐ 通则:kit 里凡是用 grid/flex 布局的容器,正文都要包一个块级元素 —— 直接塞裸文本 + <b> 会被拆成多个 grid/flex item,加粗那段被甩进下一格。仍需注意两个:.panel(flex 纵向,每个子元素各占一行)· .split(见①)。lint 查不出这个,只有渲图看得见。
✅ .warnbox 已于 2026-08-31 兜底,不再脆 —— 从 grid:auto 1fr 换成 flex + min-width:0,多塞子元素不会再让内容落错列。实测:正确写法高度 44→44(零回归),两种坏写法 102→66 / 80→48。⇒ 推荐写法仍是 .ico + 一个 <div>,但**写错不再毁版面**。
⭐ 这条值得记的不是修法,是**它是怎么被发现的**:总控 v5.8 在自己板上撞到并报过来,而正确写法当时就写在你正在读的这一行里 —— 说明「文档写了」挡不住「没人打开过文档」。⇒ 能兜底就别只写文档(与 .bar-fill / .card 同一类)。

① .split 是「一根 100% 占比条」，不是两栏布局 —— 它 height:30px;overflow:hidden，往里塞多行内容会被静默裁掉。要两栏自己写 grid-template-columns:1fr 1fr。

② .bar-fill 只写宽度,颜色挑语义（class="bar-fill crit"，可选 ok/warn/crit/mute）—— kit 自带默认色兜底，写死色值会在三套主题里其中一套翻车。③ .card 必须恰好两个子元素：.stripe + .body，塞第三个会塌成多列。

⛔ 要往 kit.css 里加新类名之前:查的是「有没有人定义过它」,不是「有没有人用过它」。
各板的补充层在 kit 之后加载 ⇒ 它覆盖 kit,所以「全机没人用这个类」完全不能证明安全。 实例:2026-08-29 新增的「带箭头的流程」原名 .flow,事前查过 class= 全机 0 命中就动了手 —— 而 iOS 板补充层早就定义了 .flow(竖排流程),被 board.py lint 当场拦下,已改名 .chain。 🔑 class= 查的是消费者,CSS 定义查的是竞争者;共享层的风险全在竞争者那一侧,而消费者数为 0 时最容易让人放心。(设计系统 v2.5 补的这句)

带箭头的流程 · chain

一件事走到哪了 —— 2026-08-29 新增
他拍了21:15
规则改完我做的
骨架在改设计系统线
渲图给他看还没到

⚠ 箭头是 CSS 用 border + rotate 画的,所以 ::after 的 content 就是空串 —— 那是设计如此,不是没生效。
判断箭头在不在,看它的宽高(应为 10×10)和边框色,别看 content。

✕ 别这么写

要竖排时给 .chain 内联一个方向。箭头会继续指向右边的空白里 —— CSS 选不中内联样式,kit 兜不住。

✓ 这么写

加语义类 col。不看视口宽度,所以嵌在多窄的容器里都成立,箭头自动转向下。

⭐ 为什么专门讲这个:.chain 最常见的用法就是嵌在窄容器里(卡内分栏 / .ba 的一栏)。而「窄屏转竖排」那条是按视口宽度判的 —— 视口 936px、容器只有 357px 时它根本不触发。
⚠ 而且 lint 不会响、整页缩略图上也看不出来 —— 总控 v5.7 实测三步量出 335/335/355(前两步各被挤掉 20px),iOS v4.5 隔离复现后已修:间距改成 column-gap/row-gap,方向由浏览器自己挑,所以现在就算内联写方向,间距也是对的,只有箭头方向还需要 col。

写法
<div class="chain">
  <div class="chain-s ok"><b>这一步</b><span>一句话补充</span></div>
  <div class="chain-s warn"><b>卡在这</b><span>等谁</span></div>
  <div class="chain-s"><b>还没到</b><span></span></div>   <!-- 不加类 = 中性 -->
</div>

<!-- 竖排(窄容器里用这个,别内联 flex-direction) -->
<div class="chain col"> … </div>
